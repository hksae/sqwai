# TUI: принципы и спецификация

Этот документ фиксирует обсуждённое направление полировки TUI до начала F7. Изменения выполняются маленькими этапами. После каждого этапа пользователь проверяет интерфейс. Функциональность не должна теряться: меняется только представление, если отдельно не оговорено обратное.

## 1. Пять принципов

### Мало элементов

Один фокус, одно поле ввода, один статус-бар. Всё остальное показывается по требованию и исчезает.

### Один ритм

Единые отступы, стиль заголовков и способ разделения. Не смешивать рамки и отсутствие рамок, разные отступы и разные символы линий.

### Цвет — редко и по смыслу

Использовать 3–4 семантических цвета. Остальное — цвет терминала по умолчанию.

### Тишина

Ничего не должно прыгать или мерцать. Каждый кадр отличается от предыдущего минимально. Один спиннер в одном месте.

### Предсказуемые клавиши

- `Esc` — назад или закрыть.
- `Enter` — выбрать или раскрыть.
- `?` — помощь.
- `j/k` и стрелки — навигация везде.
- Подсказки находятся внизу, серым цветом, только актуальные для текущего экрана.

## 2. Глобальные ограничения

- Анимированные темы полностью удалить.
- Символы: только box-drawing и `· … ▸ ▾ ✓ ✗ ◌ –`, а также braille-спиннер.
- Никаких эмодзи и «фигурных» блоков.
- `PAD_X = 1`, gutter между колонками — `2`, вертикальных отступов нет.
- Сеточные значения оформить константами, не использовать магические числа.
- `Style::default().fg(Color::…)` вне `theme.rs` запрещён. Проверять grep-ом и вычищать.
- `Block::bordered()` разрешён только для активного popup.
- Всё остальное разделяется отступами и одной горизонтальной линией.
- Верхнего бара нет.

## 3. Базовый экран

Общий вид:

```text
user › Продолжи F7 по DESIGN.md

Начинаю с блоба и BlobStore.

✓ read      src/agent/checkpoints.rs   240 lines   0.1s
✗ bash      cargo test                 exit 1      8.4s
│ error[E0308]: mismatched types
│   --> src/agent/blob.rs:47:18
│ … 38 more lines · o pager · c copy
⠋ bash      cargo test                 2.3s
─────────────────────────────────────────────────
› █
─────────────────────────────────────────────────
ACT  step 2/5 add BlobStore     thinking…   41% · 82k · sonnet
```

Порядок сверху вниз:

1. Сообщения пользователя и ассистента.
2. Строки инструментов.
3. Одна горизонтальная линия.
4. Поле ввода без рамки, с accent-префиксом `›`.
5. Одна горизонтальная линия.
6. Один статус-бар.

Сообщение пользователя: префикс accent, текст обычный. Сообщение ассистента: без префикса, обычный markdown-текст.

## 4. Статус-бар

Статус-бар — одна строка:

- слева — режим в `accent_bg`-чипе и текущий шаг плана;
- по центру — активность;
- справа — context %, токены и модель в `dim`.

Между вызовами инструментов нет пустых строк. Между сообщениями — одна пустая строка.

## 5. Строки инструментов

Свёрнутая строка имеет фиксированные колонки:

```text
статус (2) · имя (bold, ширина 9) · главный аргумент (растягивается) · результат (dim, справа) · время (dim, 5)
```

Правила:

- прошлые ходы целиком `dim`;
- цветной только символ статуса;
- имя и аргумент — обычный текст;
- результат и время — `dim`;
- главный аргумент один:
  - путь для файлов;
  - `pattern in dir` для grep;
  - команда для bash — первая значимая команда после `cd x &&`;
  - `start 2 "…"` для plan;
- JSON в строке не показывать;
- пути обрезать с `…` в середине;
- результат — host-summary из журнала: `61 passed`, `12 matches`, `+14 −2`, `exit 1`, `denied`, `cancelled`.

Статусы:

- `⠋` — выполняется, accent;
- `✓` — успешно;
- `✗` — ошибка;
- `◌` — ожидает approval, warn;
- `–` — отменено, dim.

Раскрытие:

- `Enter` на строке раскрывает её;
- используется gutter `│`, а не рамка;
- клип по ширине без wrap;
- максимум 20 строк;
- далее: `… n more · o pager · c copy`;
- diff после edit раскрывается таким же способом;
- ошибка раскрывается автоматически один раз на 8 строк и остаётся раскрытой — это единственное исключение.

Схлопывание:

- более 8 успешных подряд: первые 2 строки и `… 9 more ✓`;
- ошибки и изменения файлов не схлопываются;
- параллельные вызовы идут обычными строками подряд в порядке запроса.

Живой bash:

- справа показывать прошедшее время;
- можно показывать одну последнюю строку stdout в `dim`;
- без прокрутки stdout.

Pager — popup на весь экран из spill-файла, с прокруткой и поиском.

## 6. Popup-окна

Единый стиль:

- рамка `border`;
- заголовок в верхней линии: `┤ Sessions ├` или простой текст;
- максимум 80% ширины и высоты;
- центрирование;
- список внутри;
- выбранная строка выделяется `accent_bg` на всю ширину;
- символ `>` не использовать;
- внизу подсказки `dim`: `↑↓ move · enter select · esc close`.

Один и тот же паттерн используется для:

- моделей;
- сессий;
- ask_user;
- undo;
- skills.

`ask_user` — тот же popup:

- вопрос обычным текстом;
- варианты списком с цифрами, например `1 FastAPI async`, type hints;
- описание варианта `dim`;
- внизу `esc — свой ответ`.

## 7. Markdown в ответах

- Заголовки — bold, без отображения `#`.
- Кодовые блоки — фон на тон темнее либо без фона, но с gutter `│` и именем языка `dim` в первой строке.
- Подсветка syntect — приглушённой темой.
- Inline-код — accent без фона.
- Списки — `•` или цифры с отступом 2.
- Таблицы — нативные; если ширины не хватает, переходить к списку.
- Thinking — одна строка `thinking…` в `dim`, раскрытие по `Enter`.

## 8. Панель плана

Открывается через `Ctrl+T`.

Расположение — справа или снизу, без рамки, с одной линией-разделителем.

Содержимое:

```text
цель плана
✓ 1 explore checkpoints
▸ 2 add BlobStore
3 wire dispatcher
◌ 4 undo step N  blocked: …
```

- текущий шаг — accent;
- завершённый шаг — `✓` и dim;
- заблокированный шаг — `◌` и warn;
- счётчик evidence у текущего шага — dim, например `3 actions`;
- ничего лишнего не показывать.

## 9. Динамика и перерисовка

- Один braille-спиннер для всех живых строк.
- Шаг спиннера — 80–100 мс.
- Перерисовка только по событию, кроме спиннера.
- Стриминг дописывает текст, ничего выше не сдвигается.
- Автоследование прокрутки находится внизу.
- Если пользователь прокрутил вверх — автоследование останавливается.
- Внизу показывать `▾ new` до возврата вниз.
- Resize сохраняет позицию и фокус, кэши ширины инвалидируются.

## 10. Стартовый экран

### Что это

Стартовый экран — не отдельное состояние, а чат до первого сообщения:

- та же лента, только пустая;
- то же поле ввода с фокусом;
- тот же статус-бар;
- вместо сообщений — инфоблок;
- инфоблок исчезает при первом сообщении или команде;
- специальных клавиш нет — всё, что работает здесь, работает в обычном чате.

### Макет при ширине от 90 колонок

```text
              sqwai 0.4 · ~/dev/sqwai · main ✓ clean · sonnet

              ▸ active plan   "F7: checkpoints without git2"     step 2/5 in progress
                last session  yesterday 23:40 · 3 steps done · 1 blocked
                memory        MEMORY.md · diary 2026-09-04 · graph ready (1 180 files)

                recent        yesterday 23:40   F7 checkpoints          3 done · 1 blocked
                              2 days ago        tool calls layout       complete

                enter  continue plan      tab  plan / act      ctrl+s  sessions
                type a task to start      ?    help            /init   set up project


 ────────────────────────────────────────────────────────────────────────────────────
 › █
 ────────────────────────────────────────────────────────────────────────────────────
 ACT                                                                  0% · 0 · sonnet
```

### Содержимое сверху вниз

#### 1. Строка идентификации

Формат:

```text
sqwai <version> · <project path, сокращённый с ~> · <branch> <✓ clean | ● 3 modified> · <model>
```

Стиль — `text`, разделитель `·` — `dim`.

Если это не git-репозиторий, вместо ветки показывать `no git` в `dim`.

#### 2. Секция состояния

Это отличительная информация sqwai.

Если есть активный план:

```text
▸ active plan   "название"     step N/M in progress
  last session  yesterday 23:40 · 3 steps done · 1 blocked
  memory        MEMORY.md · diary 2026-09-04 · graph ready (1 180 files)
```

- `▸ active plan` — accent;
- название — bold;
- `step N/M in progress` — dim;
- остальные строки — dim.

Если плана нет, но есть история:

```text
no active plan · last session 2 days ago
memory        MEMORY.md · graph ready
```

Первый запуск в проекте:

```text
this project has no .sqwai yet
/init create AGENTS.md and memory or just type a task
```

Строка memory показывает только реально существующие данные:

- `MEMORY.md` — если файл существует;
- `diary <дата последней записи>`;
- `graph ready (N files)`;
- `building…`;
- `off`.

Пустые части не показывать.

#### 3. Recent

Показывать до 3 последних сессий только если:

- их хотя бы одна;
- нет активного плана, либо сессии не относятся к активному плану.

Формат:

```text
recent        yesterday 23:40   F7 checkpoints          3 done · 1 blocked
              2 days ago        tool calls layout       complete
```

Recent — только просмотр. Выбирать сессии здесь нельзя. Полный список — по `Ctrl+S`.

#### 4. Подсказки

До трёх пар в каждой строке. Колонки выровнены:

- клавиша — `text`;
- описание — `dim`;
- состав зависит от состояния;
- `enter continue plan` показывать только при активном плане;
- `/init` показывать только пока нет `.sqwai`.

#### 5. Предупреждения

Показывать под секцией состояния, без popup, максимум две строки:

```text
no API key: set ANTHROPIC_API_KEY or run /settings
git not found: undo for shell commands disabled
another sqwai instance holds this project (pid 1234) — read-only
```

Остальное доступно в `/debug`.

### Раскладка

- Блок начинается примерно с 25% высоты, не строго по центру.
- Если не помещается — прижимается к верху с отступом 1.
- Левый отступ: `max(2, (width - 84) / 2)`.
- Текст внутри выровнен по левому краю.
- Блок не центрируется построчно.
- Широкое содержимое обрезается с `…`, переносов нет.

### Узкий терминал, ширина менее 80

```text
 sqwai 0.4 · ~/dev/sqwai · main ✓

 ▸ F7: checkpoints without git2   step 2/5
   last  yesterday 23:40 · 3 done · 1 blocked
   memory  MEMORY.md · graph ready

 enter  continue plan
 tab    plan / act
 ctrl+s sessions
 ?      help
```

Для узкого терминала:

- отступ — 1;
- подсказки — в одну колонку;
- recent скрывается;
- модель убирается из первой строки, так как остаётся в статус-баре.

### Логотип

Wordmark высотой 1–2 строки — опционально, над строкой идентификации, `dim`.

Показывать только если он помещается по ширине. Не переносить. Никаких баннеров на 6 и более строк.

### Клавиши и поведение

| Действие | Поведение |
|---|---|
| Начать задачу | Печатать, `Enter` отправляет; сессия создаётся в этот момент |
| Продолжить активный план | `Enter` на пустом вводе только при активном плане; при печати задача тоже подхватывает план |
| Сессии | `Ctrl+S` |
| Режим | `Tab` |
| Помощь | `?` на пустом вводе |
| Выход | `Ctrl+D` на пустом вводе, `Ctrl+C` дважды, `/exit` |
| Настройки | `/settings` |

Убрано:

- `n`;
- `q`;
- Enter-в-меню.

Enter на пустом вводе без плана ничего не делает.

### Жизненный цикл

- Пустая сессия не создаётся при открытии приложения.
- Файл сессии появляется только после первого сообщения или команды, изменяющей состояние.
- При первом сообщении инфоблок заменяется лентой без анимации.
- Экран должен появляться мгновенно: данные берутся из уже загруженных при старте плана, diary-заголовков и сессий.
- Граф дописывается позже: `graph: building…` → `ready`.
- Git-статус вычисляется асинхронно: `main …` → `main ✓ clean`.
- `/new` на стартовом экране ничего не делает, так как сессии ещё нет.
- Resize перекладывает блок, фокус остаётся во вводе.

### Стили стартового экрана

- `text` — идентификация, названия и клавиши;
- `accent` — `▸` и префикс ввода `›`;
- `bold` — название плана;
- `dim` — разделители, время, итоги и описания клавиш;
- `warn` — предупреждения;
- `ok` — `✓ clean`.

Больше никаких цветов не использовать.

## 11. Проверка

Нужен рендер в строку через TestBackend:

```text
render_to_string(app, w, h)
```

Фикстуры:

- пустой чат;
- длинный ответ с кодом;
- 3 вызова инструментов, один упавший;
- 12 успешных вызовов, схлопнутых;
- идущий bash;
- popup ask_user;
- панель плана.

Каждая фикстура проверяется на размерах `100×30` и `70×24` через insta-snapshots.

Для стартового экрана отдельно нужны 5 фикстур на двух ширинах:

1. активный план;
2. без плана с историей;
3. первый запуск;
4. предупреждение про API key;
5. граф в процессе.

Дополнительный тест:

- после первого сообщения инфоблок отсутствует;
- файл сессии создаётся только после первого сообщения.

## 12. Порядок реализации

Работать маленькими независимыми этапами. После каждого этапа:

1. пользователь проверяет внешний вид;
2. сохраняется вся существующая функциональность;
3. выполняются тесты и проверки;
4. делается отдельный commit.

Первый этап — убрать верхний бар. Он уже выполнен отдельным коммитом:

```text
e76b2bd Remove TUI top bar
```

Следующие изменения не должны начинать F7 и не должны смешиваться с checkpoint-архитектурой.
